# 类文档模板 — 每个类完整列出方法与属性

> 本模板是 ruyi-docs `docs/php/api/` 下所有类文档的统一规范。
> 目标：让读者**完整了解这个类**——它有哪些属性、哪些方法、每个参数含义、每个方法作用，从而了解整个框架。

## 总原则

1. **方法要列全**：类的**所有方法**都要列出（public 为主，protected/private 可视重要性补充说明），不能只挑一部分。缺了方法读者就无法了解这个类的全貌。
2. **属性要列全**：类的**所有属性**（含 protected）都要列出并解释含义、默认值。
3. **每个方法**：给出**完整签名**（含类型、默认值）→ **参数逐条解释含义**（参数名 | 类型 | 默认 | 含义）→ **返回值** → **示例**。
4. **参数解释**：直接说明这个参数代表什么、取值含义即可，不需要"怎么传/传什么"这类冗词。
5. **签名、参数、属性都从源码核对**，避免与实现不符。

## 方法罗列方式建议

- 按**功能分组**组织方法（如：构造 / 装配 / 生命周期 / 静态方法），组内按调用顺序排列。
- 在页面顶部或分组处放一个「方法速查表」（方法 | 作用），让读者一眼看到这个类都有哪些方法。
- 属性同样先给速查表，再（如有必要）逐条细说。

## 说明措辞建议

| 场景 | 直接说明示例 |
|------|--------------|
| 枚举值 | 取值 `development` / `production` / `local` / `release`，对应 `Configs/` 同名文件 |
| 路径分隔 | 支持 `.` 与 `/` 分隔层级，两者等价 |
| 数组 | 关联数组，键为组件名、值为实例 |
| 布尔开关 | `true` 覆盖，`false` 合并 |
